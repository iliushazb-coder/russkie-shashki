Алгоритм нормализации: удалить каждый символ CR (0x0D); финальный LF
сохранить; BOM отсутствует, кодировка UTF-8.

Команды проверки:

    sha256sum <файл как прислан>
    tr -d '\r' < <файл> > index.mjs && sha256sum index.mjs
    node --check --input-type=module < index.mjs      # exit 0
    grep -cE 'AA[A-Za-z0-9_-]{30,}|BEGIN PRIVATE KEY-----\s*M|github_pat_|AIza[0-9A-Za-z_-]{35}' index.mjs   # 0

### Что подтверждено

  - файл из редактора побайтово совпадает с кандидатом из переписки
    (cmp exit 0 после нормализации);
  - синтаксис как ES-модуль корректен;
  - значений секретов в тексте нет — только обращения к env.*.

### Что НЕ подтверждено — читать обязательно

  1. Панель Cloudflare нигде явно не связывает общий редактор с
     идентификатором версии. Меню активной версии содержит только
     «View logs»; просмотра или выгрузки кода конкретной версии нет.
     Поэтому это доказательство УРОВНЯ СКРИПТА, а не уровня версии.
     Смягчающий факт: трафик не делится, версия одна — риск, что
     редактор показывает не то, что обслуживает запросы, невелик,
     но панелью не исключён.

  2. Пустой раздел Recent builds означает отсутствие сборочной
     истории, но НЕ доказывает отсутствие внутренних преобразований
     на стороне Cloudflare. Утверждение «развёрнут исходник как есть»
     не делается.

  3. Присланный файл пришёл с CRLF из Windows, значит его raw-байты —
     не серверные байты. Воспроизводимым хешем содержимого считается
     LF-форма с описанным выше алгоритмом.

  4. Заголовок файла «Dark settlement candidate. Not deployed.» —
     след заготовки, реальности не соответствует. Не исправлен
     намеренно: это пункт №37 MASTER PLAN, здесь файл фиксируется
     байт в байт.

  5. compatibility_date активной версии неизвестен, в wrangler.toml
     не задан. Заполнить по wrangler versions view.

Raw-формы различаются только форматированием. После канонизации:

    алгоритм                   сортировка ключей, компактные разделители,
                               завершающий LF   (эквивалент jq -cS .)
    canonical SHA-256          63a46ac332726f8a121a3f9ceca053b17765d1d8ef3ea22a04d4d5d3578c8271
    обе копии                  совпадают, cmp exit 0

    в репозитории              firebase/database.rules.json — JSON с
                               отступами; canonical SHA-256 тот же
                               63a46ac3…

Внимание к деталям канонизации: без завершающего LF хеш другой
(5f6d42aa…). При повторной сверке использовать jq -cS . либо
эквивалент с добавлением LF.

шести несекретных. Два секрета представлены ТОЛЬКО именами.

переменные и активную версию как два отдельных факта.

compatibility_date неизвестен и не задан. Конфигурация не готова к
deploy до получения настоящего production-значения.

script.js клиента и по замыслу Firebase публичен; доступ ограничивают
правила и App Check.
